OliSnack API.

Dados e nutrição com sotaque brasileiro. API de pratos regionais brasileiros com catálogo, cálculo nutricional por ingrediente e autenticação para operações de escrita.

PythonFastAPIPostgreSQLDockerJWT

O ponto de partida.

Problema
Disponibilizar informações de pratos brasileiros em uma estrutura que outras aplicações possam consultar.
Solução
Um catálogo persistido em PostgreSQL, exposto por FastAPI, com cálculo de nutrientes e exportação estática para frontends.
Desafio técnico
Manter coerência nos cálculos, evolução do banco e controle de acesso às alterações.

Como as peças se conectam.

  1. ClienteBusca pratos ou envia ingredientes.
  2. FastAPIValidação, endpoints e autenticação.
  3. ServiçosCatálogo e cálculo nutricional.
  4. PostgreSQLPratos, ingredientes e usuários.

A API oferece rotas de busca, catálogo e cálculo de refeições. PostgreSQL mantém os dados; migrations acompanham a evolução do schema. Docker Compose organiza o ambiente da API e do banco. A consulta externa ao FatSecret é opcional.

Decisões de desenvolvimento.

  • Catálogo reproduzível. O seed carrega 46 pratos regionais e pode ser repetido sem duplicá-los. Migrations tornam explícita a evolução da estrutura do banco.
  • Escrita autenticada. Tokens JWT identificam usuários e operações administrativas. A API impede a desativação do último administrador ativo e limita tentativas repetidas de login.
  • Frontend sem backend permanente. O exportador gera um catálogo JSON público a partir dos dados curados. Sites apenas de consulta podem usar esse arquivo e filtrar localmente.
  • Saúde do serviço. Endpoints separados de liveness e readiness permitem diferenciar um processo ativo de uma aplicação com banco disponível.

Desafios e limites atuais.

A exportação JSON precisa ser atualizada quando os dados curados mudam. A consulta externa depende de configuração própria. Os valores descrevem ingredientes e porções cadastrados; não representam uma prescrição individual.

O README inclui uma suíte pytest com banco de teste separado, testes específicos de nutrição e comandos para cobertura. A documentação interativa permite explorar os endpoints em uma instalação local.

Possíveis próximas evoluções.

Caminhos de evolução a explorar, sem previsão de entrega.

  • Ampliar a curadoria dos pratos e revisar a rastreabilidade dos dados.
  • Evoluir integrações consumidoras do catálogo estático e da API.
  • Acompanhar consistência e desempenho conforme o catálogo crescer.

Experimente no seu ambiente.

O README descreve a execução com Docker Compose, a carga inicial dos dados e o acesso à documentação interativa em /docs. As credenciais de escrita são configuradas no ambiente local.
